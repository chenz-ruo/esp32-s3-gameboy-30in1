# 验收记录、已修问题与遗留项

## 1. 自动化验收方法

板子没有屏幕录制条件，因此用串口协议（`docs/BUILD.md` 第 5 节）驱动固件：

- `i` 回读 `>where=...`，确认状态机走到 `MENU / INTRO / PLAY / RESULT`；
- `p` / `P` 注入短按 / 长按，`n` 翻页；
- `S` 回读 RLE 帧缓冲，主机侧解码成 PNG 逐屏核对排版；
- 逐项跑 `MENU → INTRO → PLAY`，全程扫描日志里的 `panic` / `Guru Meditation`；
- 判定类用**乱按模式**跑多轮，把正确率与理论概率分布比对；
  只验证"能跑完、不崩溃"是不够的，必须看**分数分布**才能发现"怎么按都对"。

最后一次系统级结果：

```
panic lines: none
>where=PLAY:REFLEX
speaker up, volume 80
```

整理仓库后另做了一次完整编译验证（`idf.py build`，ESP-IDF v6.1 / xtensa
`esp-15.2.0_20251204`）：`BUILD_EXIT=0`，生成 `box1play.bin` 0x86E60（约 552 KB），
app 分区 0x300000 剩余 82%，无编译错误。构建脚本因此补齐了
`ESP_IDF_VERSION` 与 `ESP_ROM_ELF_DIR` 两个环境变量。

## 2. 逐类结论

| 类别 | 数量 | 结论 |
| --- | --- | --- |
| 通用判定引擎 | 16 | 未发现逻辑 bug，乱按正确率与理论概率在统计噪声内一致 |
| 机制 / 反应 / 记忆类 | 14 | 除 `COUNT` 在 24 s 自动化窗口内打不完外，均可完成、无负分、无崩溃 |
| `REFLEX` 乱按 | — | 抢跑后本回合作废重来，打不完一局是**设计行为**，不是 bug |

## 3. 已修问题清单

| 问题 | 根因 | 修复 |
| --- | --- | --- |
| 上电「1、3 都被选中」+ 底部花屏 | 菜单首帧只刷局部，下半屏仍是上电随机显存 | 首帧 / 返回菜单强制整屏 `s_full_frame` |
| 缺行、拖影、像素延迟 | 二值信号量残留 token 让 `bsp_lcd_wait()` 提前返回 | 改 `s_trans_done` / `s_pending_id` 计数等待，且 `s_pending_id` 必须在 `draw_bitmap()` **之后**记录 |
| 滑块闪一下、左右消失不同步、上方菜单显示不全 | 脏带只覆盖滑块扫过区域；标题带没纳入刷新；横屏 MV 旋转让撕裂线是竖向 | 大跨度跳转整列表刷新、标题带并入脏带并最后重绘、进度条用 `present_strip()` 独立刷、20 MHz、改原生竖屏 |
| 滑动时上行文字提前变淡 | 按覆盖度在深灰/白之间混色 | 改为跟随最近一行 `lroundf(s_sel_f)` 的硬切换 |
| 深色→亮色混色出现色块 | `gfx_mix()` 用无符号通道差值下溢 | 改成 `int` 有符号计算 |
| 菜单滑到底绕回顶部 | `app_move()` 用了取模回卷 | 改成 clamp 到 `[0, GAME_COUNT-1]` |
| 竖屏后引导页文字被裁切 | 18 px 中文串超过 240 px 可用宽度 | `ui_wrap()` 按 UTF-8 码点断行 + 标点断行规则 |
| 卡片内文字偏下 | 行高 44→40→38 后文字 y offset 未同步 | 按 38 px 行高重算 `+3/+6` |
| 「抗干扰」等 7 个游戏大字空白 | `font_52` 只生成数字/字母，缺中文和几何符号 | `gen_font_box.py` 的 `extra` 加 `红绿蓝←●▲■◆★○△□◇` |
| 去掉底部说明后游戏页大片空白 | 删 `ui_hint()` 时连游戏内状态说明一起删了 | 新增 `ui_note()`，各状态给一行说明 |
| 完全没有声音 | ES8311 初始化后默认 mute + 音量 0；功放使能极性写反；IDF 6.1 缺旧 I2S 头 | 显式 unmute / volume 65，功放写 1，改用 `i2s_std.h`，加 `myiic` shim |
| 音量 10%/40% 近乎无声 | DAC 增益与数字幅度串联双重衰减；自动化测试把音量调到 10 | 对照官方例程改成 DAC 固定 65、数字域调音量、增益 0.80；开机 `<40` 恢复到 80 |
| 进第一个游戏就重启 | `TRACKS[]` 开头留了 `{0}` 占位，`audio_bgm(0)` 解引用 NULL | 删除占位项、索引与游戏编号严格对齐、加三重空指针保护 |
| `Track.step_us` 编译溢出 | 慢曲 70000–120000 µs 超过 `uint16_t` | 结构字段改 `uint32_t` |
| 「图形判断」什么图形都对 | 占位表达式判断 UTF-8 首字节，四种图形都满足 | 按生成时的随机下标判定：`answer = (i == 0)` |
| 「时间感知」正确答案不可达 | 阈值 2000 ms，但答题窗口只有 1700 ms | 阈值改 1200 ms，文案改「稍等约 1 秒」 |
| 「节奏环」出现负数不可打破的纪录 | 有符号早/晚误差存进了统计数组 | 统计存绝对值、反馈保留符号；NVS 加载时丢弃「越小越好」类型的负数旧纪录 |
| 亮度调不下来 | 背光是扩展 IO 纯开关，`0x51` 不接背光电路 | 保留接口、恢复 100，改用深色主题降低视觉亮度 |
| `QFDef` 编译报错 | `-Werror=missing-field-initializers` | 补齐所有初始化字段 |
| 旧 I2C 头弃用警告被 `-Werror` 拦截 | IDF 6.x EOL 警告 | `CONFIG_I2C_SUPPRESS_DEPRECATE_WARN=y` |

## 4. 遗留 / 待确认

- **开机音量偶发自动降 10%**：疑似上电瞬间某个按键被读成按下，逐级下调。
  目前用「读到 `<40` 就恢复 80 并写回 NVS」兜底，**根因未彻底定位**。
- **`COUNT`（编号 10）一局偏长**：5 回合，自动化 24 s 窗口常打不完，
  可压缩显示/输入时长或改成 4 回合。
- **判级阈值**：脚本验证了逻辑与概率分布，"闪电 / 优秀 / 良好"的手感是否
  合理仍需真人多轮试玩确认。
- **音乐听感**：30 条手写旋律已烧录并确认不再崩溃，但"每首是否足够不一样、
  节奏感够不够"需要真人确认。
- **99 个游戏**：目前完成 30 个，剩余 69 个未写；后续新增仍保持单列平铺、不分组。
- **撕裂**：无 TE 引脚，只能减轻不能彻底消除；竖屏 + 20 MHz + 局部刷新后观感已可接受。

## 5. 手动回归清单（烧录后快速过一遍）

1. 上电：两声提示音、菜单首屏完整、只有一项高亮、右侧进度条可见、LED 全灭。
2. K0/K1 短按逐项移动；长按 0.3 s 后开始连发、0.9 s 后明显加速；到底停住不回卷。
3. 任意游戏：K2 短按进入、引导页规则完整换行、游戏内有一行状态说明、结算显示
   本局值与历史最佳、K2 长按返回菜单。
4. 分别进 12「抗干扰」、16「同色判断」、30「图形判断」，确认大字不空白、
   判定不是"怎么按都对"。
5. 游戏中 K0/K1 调音量，确认有变化且不会突然静音。
6. 菜单中 K0+K1+K2 按住 1 s，确认成绩全部清零并有提示音。
